# Лабораторная работа №1 — Вариант 3

**Тема:** Композиция и агрегация классов. Статические члены.

**Дисциплина:** Алгоритмы и структуры данных

---

## Цель работы

1. Научиться проектировать отношения между классами: композицию, агрегацию и ассоциацию.
2. Освоить реализацию композиции (поля-объекты, вложение структур) и агрегации (указатели, ссылки).
3. Понять разницу между композицией и агрегацией с точки зрения времени жизни объектов.
4. Научиться использовать статические поля и методы для подсчёта объектов и реализации общих данных для всех экземпляров класса.
5. Получить навыки правильного управления памятью при разных типах отношений между классами.

---

## Постановка задачи

**Средний уровень.** Реализовать два класса, связанных отношением агрегация (часть может существовать без целого). Добавить статическое поле для подсчёта количества объектов класса «Часть». Продемонстрировать, что при уничтожении целого части продолжают существовать.

---

## Решение

Реализованы два класса:

- **`Student`** — «часть» в агрегации, может существовать без курса. Содержит статическое поле `totalCount` для подсчёта всех созданных студентов.
- **`Course`** — «целое», хранит вектор указателей `vector<Student*>`, не удаляет студентов в своём деструкторе.

### Основные моменты реализации

- **Статическое поле** `int Student::totalCount` объявлено внутри класса и определено вне его (`int Student::totalCount = 0;`).
- **Конструктор** `Student` увеличивает счётчик, **деструктор** — уменьшает.
- **`Course::addStudent()`** принимает указатель с проверкой на `nullptr`.
- **Деструктор `Course`** не удаляет студентов — они живут отдельно.

---

## Результаты работы

В ходе выполнения программы продемонстрировано:

1. Созданы 3 студента — счётчик `totalCount` равен 3.
2. Создан курс в отдельном блоке `{}`, на него добавлены студенты.
3. При выходе из блока курс уничтожается, но студенты остаются — счётчик по-прежнему 3.
4. В конце программы студенты уничтожаются вручную или автоматически.
